# Безопасность файлового API — защитные проверки и матрица

Роль 05-security. Директория `tests/security/`, доказательства `artifacts/<run_id>/security/`.
Область — **штатный обмен на собственных данных** обычным HTTP-клиентом. Сетевой
пентест и атаки на чужие данные сюда **не входят**: для них подготовлено отдельное
задание — [pentest-brief.md](pentest-brief.md).

Ключевое различие, которое обязана держать эта роль:

- **Эмпирическое наблюдение** — свойство, подтверждённое ответом сервиса в прогоне.
- **Обещание окружения** — свойство, заявленное в профиле (`sources`: `agreement`/`stand`),
  но не проверяемое снаружи обычным запросом.

Неизвестная модель публичности и одиночный запрос по HTTP оставляют соответствующий
вопрос **открытым** — это фиксируется как наблюдение, а не как провал.

## Матрица «актив / требование / свидетельство / проверка / влияние»

| ID | Актив | Требование | Доступное свидетельство | Проверка | Влияние при нарушении |
|---|---|---|---|---|---|
| SEC01 | Точка входа (транспорт) | Фактическая схема (HTTP/HTTPS) на объявленной точке входа; учётные данные в штатном запросе отсутствуют, если профиль их не требует | Схема из `urlsplit(origin)`; заголовки ответа `/health` (нет `www-authenticate`) | Авто: `test_transport.py` | Без TLS — перехват/подмена в пути; непроверенная авторизация — доступ к чужим данным |
| SEC02 | Выдача вложения | `Content-Disposition: attachment`, корректное имя, `Content-Type` без сниффинга | Заголовки `GET /files/{name}` собственного файла | Авто: `test_delivery.py` | Инлайн-рендер → stored-XSS; подмена MIME → исполнение браузером |
| SEC03 | Публичная схема | Отсутствие лишних внутренних полей (внутренний путь `/var/example-store/…` в `path`) | Квитанция `POST /files` и список `GET /files` | Авто: `test_public_schema.py` | Info disclosure: раскрытие внутренней раскладки хранилища |
| SEC04 | Диагностические ответы | 404/400 не раскрывают стектрейсы, абсолютные пути, имена внутренних модулей | Тело ответов `GET /files/{missing}` и `POST /files` без файла | Авто: `test_diagnostics.py` | Утечка внутренностей упрощает атаку; раскрытие структуры |
| SEC05 | Собственные артефакты | Синтетический секрет отсутствует в отчёте/артефактах; чувствительные заголовки не сохраняются | Скан `artifacts/<run_id>/security/`; whitelist `KEEP_HEADERS` | Авто (офлайн): `test_hygiene.py` | Утечка секретов в репозиторий/CI-артефакты |
| SEC06 | Конфигурация | Лимиты, роли, срок хранения сверены с профилем; отсутствующее — вопрос владельцу | Профиль (`limits`, `security.roles`, `security.retention`, `sources`) | Авто + ручная: `test_configuration.py` | Несогласованные лимиты/хранение → скрытые риски ёмкости и удержания |

## Результаты и основания по каждой проверке

Статусы: `observation` — зафиксировано наблюдение; `pass` — свойство подтверждено;
`incomplete` — не доведено до сравнения (например, стенд недоступен).

| ID | Результат | Основание (наблюдение / обещание) |
|---|---|---|
| SEC01 | Схема — **наблюдение** (фактическая); авторизация — **наблюдение** (нет challenge) | Профиль `security.example.json` заявляет `transport=http`, `auth=none-observed` (источник `observation`). Это обещание окружения о текущем стенде, а не проверяемое требование. Один запрос по HTTP оставляет вопрос «должен ли быть TLS» открытым до согласования модели публичности |
| SEC02 | `attachment` и имя — **наблюдение** | Заголовки выдачи подтверждаются ответом на собственный файл. Требование «имя согласно политике» выполнимо только при согласованной политике имён (`policy.names`) |
| SEC03 | Внутренний путь в публичной схеме — **проверяемое наблюдение** | Квитанция/список раскрывают `path=/var/example-store/…`. При `disclosure_policy=no-internal-path` это несоответствие (тест падает); при `unknown` — фиксируется, вопрос открыт |
| SEC04 | Минимальность ошибок — **наблюдение** (проверка на утечки) | Тело 404/400 проверяется на стектрейсы/абсолютные пути/модули; в evidence сохраняется только короткий обезличенный фрагмент |
| SEC05 | `pass` (автономно) | Синтетический секрет не попадает в манифест/карточки; чувствительные заголовки (`authorization`, `cookie`, …) не в `KEEP_HEADERS` |
| SEC06 | **Наблюдение + вопросы** | Заявленные лимиты проверяются на корректность; роли/срок хранения в профиле не заданы — выносится вопрос владельцу, не провал |

## Открытые вопросы

1. **Модель публичности не согласована** — кому разрешено перечислять, скачивать и
   загружать файлы. Пока ответа нет, отсутствие авторизации и раскрытие внутреннего
   пути остаются «наблюдением», а не «дефектом». Адресат: **владелец продукта**.
2. **Транспорт — HTTP без TLS** (один наблюдаемый запрос). Допустимо только если
   сервис публичный обменник и TLS терминируется перед ним. Адресат: **владелец
   сервиса** (где завершается TLS).
3. **Срок хранения и роли не заданы** в профиле. Адресат: **владелец сервиса**
   (хранение) и **владелец продукта** (роли).

## Запуск

```sh
cd framework
# сбор без исполнения
python3 -m pytest tests/security --collect-only -q

# фактический прогон на стенде (обычные ответы, собственные данные)
FILEQA_PROFILE=profiles/security.example.json \
FILEQA_ORIGIN=http://files.example.com \
  python3 -m pytest tests/security -q
```

Доказательства — `artifacts/<run_id>/security/{SEC01..SEC06,SEC-REACH}.json`.
